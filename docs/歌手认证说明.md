# 歌手认证说明

## 规则

- 只有状态为 `APPROVED` 的音乐人才能提交歌手认证。
- 认证申请会使用音乐人的艺名、头像和简介创建歌手档案。
- 提交后进入管理员审核，状态为：`0 待审核 / 1 已认证 / 2 未通过`。
- 未通过后可以修改资料重新提交；已认证歌手可以进入歌手频道主页。
- 非音乐人调用接口会返回「请先完成音乐人认证，再申请歌手认证」。

## 流程

```
音乐人工作台 → 歌手认证
   │  POST /api/music/singers/apply
   ▼
music-service 校验 musician-service 中的音乐人状态
   ├─ 非音乐人 / 未通过 → 拒绝
   └─ 已认证音乐人 → 创建 singer(status=0)
   ▼
管理员：歌手管理 → 审核
   ├─ 通过 → status=1，进入公开歌手列表
   └─ 拒绝 → status=2，记录拒绝原因
```

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/music/singers/mine` | 当前用户的歌手认证记录 |
| POST | `/api/music/singers/apply` | 提交 / 重新提交歌手认证 |
| GET | `/api/music/singers/admin/page` | 管理员查看歌手与待审申请 |
| POST | `/api/music/singers/admin/{id}/audit` | 管理员审核，参数 `approved`、`reason` |

## 数据库升级

全新部署执行 `sql/01-schema.sql`。已有数据库执行一次：

```bash
docker exec -i kumao-mysql mysql -uroot -pkumao123456 --default-character-set=utf8mb4 < sql/09-singer-certification.sql
```

新增 `singer.musician_id / user_id / reject_reason / audit_time`，并增加 `musician_id` 唯一索引。管理员删除歌手时会先释放 `musician_id`，允许该音乐人重新申请。
