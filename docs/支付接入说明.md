# 支付接入说明（支付宝沙箱 + 微信支付）

VIP 会员、酷猫币充值与广告投放费用共用 **支付宝电脑网站支付（沙箱/生产）** 与 **微信支付 APIv3 Native 扫码支付**，并保留本地模拟支付用于无商户参数时的开发演示。

## 一、支付流程

```
前端 VIP 页 / 直播间钱包
   │  POST /api/vip/vip/pay/create  { packageId, payType }
   │  可选：VIP 套餐 id / 酷猫币套餐 id（vip_package.type=COIN）
   │  或 POST /api/vip/vip/pay/ad/create  { planId, payType }
   ▼
vip-service 创建 vip_order（UNPAID，30 分钟有效）
   ├─ 支付宝：返回 payUrl，浏览器跳转支付宝收银台
   ├─ 微信：调用 Native 下单，返回 code_url，服务端生成二维码
   └─ 未配置渠道：降级 MOCK，返回 mock=true
   ▼
用户支付
   ├─ 支付宝异步通知 POST /api/vip/vip/pay/alipay/notify
   ├─ 微信异步通知   POST /api/vip/vip/pay/wechat/notify
   └─ 前端轮询 GET /api/vip/vip/pay/status/{orderNo}（主动查单兜底）
   ▼
验签 + 金额校验 + 条件更新（UNPAID → PAID）
   ▼
发放权益
   ├─ VIP 套餐：vip_member 续期 + 同步用户 VIP 角色
   ├─ 酷猫币套餐：调用 live-service 内部接口幂等加币（live_coin_recharge 留痕）
   └─ 广告投放：调用 ad-service 内部接口标记 payment_status=PAID，等待管理员审核投放
```

关键设计：

- **幂等**：`markPaid` 使用 `UPDATE ... WHERE status <> 'PAID'` 条件更新，只有更新成功的请求才发放权益，重复回调不会重复加天数或重复加币。
- **验签**：支付宝使用 RSA2 验签并校验 `app_id`；微信使用官方 SDK 校验 `Wechatpay-Signature` 并 AES-GCM 解密回调。
- **金额校验**：回调金额必须与订单金额一致，否则拒绝入账。
- **主动查单**：本地开发收不到异步通知时，前端轮询 `/status` 会触发 `alipay.trade.query` / 微信查单接口补单。
- **回调留痕**：原始报文写入 `pay_notify_log`，方便对账与排障。
- **超时关单**：定时任务每分钟关闭超过 30 分钟未支付的订单。

## 三、配置项

配置位于 `vip-service/src/main/resources/application.yml` 的 `kumao.pay`，全部支持环境变量覆盖。

### 通用

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `PAY_MOCK_ENABLED` | `true` | 渠道未配置时是否允许本地模拟支付，生产设为 `false` |
| `PAY_NOTIFY_BASE_URL` | `http://127.0.0.1:8080` | 支付回调基础地址，必须是支付平台可访问的公网地址 |
| `PAY_ORDER_TIMEOUT_MINUTES` | `30` | 订单支付超时时间（分钟） |

### 支付宝

| 环境变量 | 说明 |
|---|---|
| `ALIPAY_ENABLED` | `true` 启用真实支付宝支付 |
| `ALIPAY_APP_ID` | 沙箱/生产应用 APPID |
| `ALIPAY_PRIVATE_KEY` | 应用私钥（PKCS8，去掉 `BEGIN/END` 头，单行） |
| `ALIPAY_PUBLIC_KEY` | 支付宝公钥（用于回调验签，不是应用公钥） |
| `ALIPAY_GATEWAY_URL` | 默认沙箱 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`；生产改为 `https://openapi.alipay.com/gateway.do` |
| `ALIPAY_RETURN_URL` | 支付完成浏览器回跳地址，默认 `http://127.0.0.1:5173/#/vip`；从直播间充值时可改为对应直播间地址或由前端统一处理 |

### 微信支付

| 环境变量 | 说明 |
|---|---|
| `WECHAT_PAY_ENABLED` | `true` 启用微信支付 |
| `WECHAT_APP_ID` | 与商户号绑定的 APPID（公众号/小程序） |
| `WECHAT_MCH_ID` | 商户号 |
| `WECHAT_MERCHANT_SERIAL_NO` | 商户 API 证书序列号 |
| `WECHAT_PRIVATE_KEY_PATH` | 商户 API 私钥文件路径，如 `D:/certs/apiclient_key.pem` |
| `WECHAT_PRIVATE_KEY` | 也可直接传 PEM 私钥内容（与上一项二选一） |
| `WECHAT_API_V3_KEY` | APIv3 密钥（32 位） |
| `WECHAT_NOTIFY_URL` | 可选，单独指定微信回调地址 |

> 微信支付 **没有公开沙箱**（旧版 v2 沙箱已下线），本地演示请保持 `WECHAT_PAY_ENABLED=false` 走模拟支付；上线时使用真实商户号。

## 四、支付宝沙箱配置步骤

1. 登录 [支付宝开放平台](https://open.alipay.com/) → 控制台 → 沙箱环境，获得 **沙箱 APPID** 和沙箱买家账号。
2. 下载「支付宝密钥生成工具」，选择 **RSA2**，生成应用私钥/应用公钥。
3. 在沙箱应用 → 开发信息 → 接口加签方式中上传 **应用公钥**，平台会生成 **支付宝公钥**。
4. 将 APPID、应用私钥、支付宝公钥填入环境变量，设置 `ALIPAY_ENABLED=true`。
5. 回调地址要求公网可达：本地开发用内网穿透把 8080 暴露出去，例如：
   ```bash
   ngrok http 8080
   ```
   然后设置 `PAY_NOTIFY_BASE_URL=https://xxxx.ngrok-free.app`。
6. 启动后访问 `http://localhost:5173/#/vip`，点击「立即开通」→ 支付宝 → 在沙箱收银台使用沙箱买家账号付款。

## 五、微信支付配置步骤

1. 商户平台 → 账户中心 → API 安全：设置 **APIv3 密钥**，申请 **商户 API 证书**（得到 `apiclient_key.pem` 与证书序列号）。
2. 确认 APPID 与商户号已绑定，且开通 **Native 支付** 产品权限。
3. 配置环境变量：`WECHAT_PAY_ENABLED=true`、`WECHAT_APP_ID`、`WECHAT_MCH_ID`、`WECHAT_MERCHANT_SERIAL_NO`、`WECHAT_PRIVATE_KEY_PATH`、`WECHAT_API_V3_KEY`。
4. 回调地址 `PAY_NOTIFY_BASE_URL` 必须是 HTTPS 公网地址（微信要求）。
5. 用户在前端选择微信支付后展示二维码，扫码完成支付；前端每 2.5 秒轮询订单状态。

## 六、接口清单

| 方法 | 路径（网关入口） | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/vip/vip/pay/channels` | 登录 | 查询可用渠道 |
| GET | `/api/vip/vip/pay/coin/packages` | 公开 | 查询酷猫币充值套餐 |
| POST | `/api/vip/vip/pay/ad/create` | 登录 | 创建广告投放费用支付订单 |
| POST | `/api/vip/vip/pay/create` | 登录 | 创建支付订单（VIP 套餐或酷猫币套餐） |
| GET | `/api/vip/vip/pay/status/{orderNo}` | 登录 | 查询订单状态（含主动查单） |
| POST | `/api/vip/vip/pay/mock/{orderNo}/success` | 登录 | 本地模拟支付成功（仅 MOCK 订单） |
| GET | `/api/vip/vip/pay/alipay/page/{orderNo}` | 公开 | 支付宝收银台表单 |
| POST | `/api/vip/vip/pay/alipay/notify` | 验签 | 支付宝异步通知 |
| POST | `/api/vip/vip/pay/wechat/notify` | 验签 | 微信支付异步通知 |

旧接口 `POST /api/vip/vip/open` 保留兼容：`payType=MOCK` 时直接完成支付，其他渠道返回支付参数。

## 七、本地模拟支付

默认 `PAY_MOCK_ENABLED=true` 且两个渠道均未配置，因此：

- 前端支付弹窗会标注「未配置 · 模拟支付」；
- 点击支付会弹窗确认，确认后调用 `/mock/{orderNo}/success` 完成订单并开通会员、到账酷猫币或标记广告投放已付费；
- 酷猫币充值成功后调用 live-service 内部接口入账，`live_coin_recharge.order_no` 唯一，重复回调不会重复加币；
- 广告投放费用按「版位日单价 × 投放天数」计算，支付成功后才允许管理员审核投放。
- 不会产生任何真实扣款，适合演示与自动化测试。

上线前务必设置 `PAY_MOCK_ENABLED=false`，避免误用模拟支付。

## 八、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 支付宝返回 `invalid-signature` | 应用私钥与上传到开放平台的应用公钥不匹配；或误把应用公钥当支付宝公钥使用 |
| 支付宝提示 `isv.app-id-not-match` | `ALIPAY_APP_ID` 与密钥不匹配 |
| 支付成功但会员未开通 | 检查 `PAY_NOTIFY_BASE_URL` 是否公网可达；查看 `pay_notify_log`；前端轮询 `/status` 可主动补单 |
| 微信返回 401 / 签名错误 | 检查商户号、证书序列号、私钥、APIv3 密钥是否匹配 |
| 微信回调 500 | 查看 `pay_notify_log` 与 vip-service 日志；确认金额与订单一致 |
| 本地收不到回调 | 使用 ngrok/cpolar 内网穿透，或依赖前端轮询主动查单 |
