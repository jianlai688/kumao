# 手机 App「网络异常」解决方案

> 现场环境：Windows 主机 `D:\kumao`，本机局域网 IP `192.168.20.103`，Android 设备 `emulator-5554`（USB/adb 已连接）。
> 结论先行：**APK 里的接口基址是 `http://127.0.0.1:8080/api`，手机上 127.0.0.1 指向手机自己，不是电脑；当前又没有建立 adb reverse，所以所有接口都会报网络异常。**

---

## 一、现场现象

- App 能打开、静态页面正常，但首页榜单、新歌、直播等接口数据为空；
- 请求失败时 App 弹出「网络异常」；
- `adb reverse --list` 为空；
- 已安装 APK 版本：`com.kumao.music 1.5.0`（修复前），属于 **USB 版**（接口基址 `127.0.0.1:8080`）；
- 本机网关 `http://127.0.0.1:8080` 正常，SRS/业务服务也正常。

## 二、根因

### 1. 直接原因：USB 版 APK 没有配套的 ADB 反向隧道

USB 版 APK 编译时写入了：

```text
http://127.0.0.1:8080/api
```

这个地址在电脑浏览器里是电脑自己，但在手机/模拟器里是**手机自己**。必须通过数据线建立反向映射：

```text
手机 127.0.0.1:8080  --adb reverse-->  电脑 127.0.0.1:8080
```

没有映射时，请求根本到不了网关，只能报「网络异常」。

### 2. 次生原因：Wi-Fi 版 APK + Windows 防火墙

如果安装的是 Wi-Fi 版（接口基址 `http://192.168.20.103:8080/api`），还需要：

- 手机和电脑在同一局域网（`192.168.20.x`）；
- Windows 防火墙放行 `8080 / 8088 / 1935 / 5173`；
- 当前系统网络为「公用」，且没有 `Kumao-*` 入站规则，默认会被防火墙拦截。

### 3. 常见混淆点

仓库里同时存在两种 APK：

| 版本 | 接口基址 | 适用场景 |
|---|---|---|
| `KuMao-Android-v1.5.1-usb.apk` | `http://127.0.0.1:8080/api` | USB 数据线 + `adb reverse` |
| `KuMao-Android-v1.5.1.apk` | `http://192.168.20.103:8080/api` | 手机与电脑同一 Wi-Fi |

**两种包不能混用**：USB 包装到 Wi-Fi 环境、Wi-Fi 包装到没有局域网的环境，都会表现为「网络异常」。

## 四、按场景选择解决方案

### 方案 A：USB 数据线（当前设备，推荐）

适用：手机没有 Wi-Fi、Wi-Fi 与电脑不同网段、公司网络限制多。

1. 手机开启「开发者选项 → USB 调试」，数据线连接电脑，授权调试。
2. 安装 USB 版 APK：

```powershell
adb install -r "D:\kumao\kumao-web\public\downloads\KuMao-Android-v1.5.1-usb.apk"
```

3. 建立反向映射并启动：

```powershell
pwsh -File scripts\usb-phone-debug.ps1 -Launch
```

4. 验证：
   - 手机浏览器打开 `http://127.0.0.1:8080/api/music/rank/hot?limit=1`，应返回 JSON；
   - App 首页有榜单/新歌数据。

> `adb reverse` 在拔线、手机重启、adb server 重启后会失效，重新执行脚本即可。建议把脚本固定到桌面快捷方式。

### 方案 B：同一 Wi-Fi（无线演示）

适用：手机与电脑连接同一路由器，且能修改 Windows 防火墙。

1. 安装 Wi-Fi 版 APK：

```powershell
adb install -r "D:\kumao\kumao-web\public\downloads\KuMao-Android-v1.5.1.apk"
```

2. 管理员 PowerShell 放行端口（当前系统未放行）：

```powershell
New-NetFirewallRule -DisplayName "Kumao-8080-网关" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080 -Profile Any -RemoteAddress 192.168.20.0/24
New-NetFirewallRule -DisplayName "Kumao-8088-HLS"  -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8088 -Profile Any -RemoteAddress 192.168.20.0/24
New-NetFirewallRule -DisplayName "Kumao-1935-RTMP" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 1935 -Profile Any -RemoteAddress 192.168.20.0/24
New-NetFirewallRule -DisplayName "Kumao-5173-前端" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5173 -Profile Any -RemoteAddress 192.168.20.0/24
```

3. 手机连接同一 Wi-Fi（必须是 `192.168.20.x` 网段，不要连访客 Wi-Fi）。
4. 手机浏览器访问 `http://192.168.20.103:8080/api/music/rank/hot?limit=1`，返回 JSON 后打开 App。
5. 直播还需要重启 `live-service` 时注入：

```powershell
$env:SRS_PLAY_HOST = 'http://192.168.20.103:8088'
$env:SRS_PUSH_HOST = ''
```

### 方案 C：电脑 IP 变化 / 换网络

不要手动改 `assets` 里的 JS，直接重新构建：

```powershell
pwsh -File scripts\build-mobile-apk.ps1 -Mode wifi -ApiBase http://<新IP>:8080/api
```

然后把新 APK 安装到手机。长期演示建议在路由器上给电脑做 **DHCP 地址保留**，避免 IP 变化。

### 方案 D：手机用 4G / 异地访问

不要把 `8080 / 8101~8111 / 3306 / 6379 / 9000` 直接映射到公网。推荐：

- Tailscale / ZeroTier 组虚拟局域网；
- 或 Cloudflare Tunnel / frp 只暴露网关 `8080`，并保留 JWT 鉴权。

然后按方案 C 用隧道域名重新打包 APK。

## 六、以后如何避免

1. **明确装的是哪版 APK**：USB 版文件名带 `-usb`，Wi-Fi 版不带。
2. **先验证网络再打开 App**：手机浏览器请求一次网关 JSON，比看 App 报错更快。
3. **每次重新插线/重启手机后跑一次** `scripts\usb-phone-debug.ps1`。
4. **换电脑 IP 后用脚本重打包**，不要手工替换 APK 内的 JS。
5. 更彻底的方案：在 App 内增加「服务器地址」设置页，把 API 基址存到本地存储，运行时读取；这样同一个 APK 可在 USB / Wi-Fi / 隧道之间切换。需要的话可以继续实现。

## 五、方案 C：公网版 APK（推荐，已产出）

网站已通过 Nginx + cpolar 发布到公网后，可以直接把接口基址打进 APK，
手机**不用数据线、不用同一 Wi-Fi、不用改防火墙**，4G/5G 就能用。

```text
D:\kumao\kumao-web\public\downloads\KuMao-Android-v1.5.2-public.apk
公网下载：https://<cpolar域名>/downloads/KuMao-Android-v1.5.2-public.apk
接口基址：https://<cpolar域名>/api
```

重新构建（域名变了就重跑一次，把 -ApiBase 换成新域名）：

```powershell
pwsh -File scripts\build-mobile-apk.ps1 -Mode wifi -ApiBase https://<当前隧道域名>/api
# 产物在 kumao-web\public\downloads\KuMao-Android-v<版本>.apk，再改名加 -public 后缀
```

要点：

- WebView 内部页面源是 `http://127.0.0.1:8099`，调公网 HTTPS 属于跨域，网关
  `CorsConfig` 已 `addAllowedOriginPattern("*")`，预检实测 200；
- 直播 WebSocket 由 `utils/live.js` 按 API 基址协议自动切到 `wss://`；
- **cpolar 免费版子域名是随机的**，域名一变 APK 里的基址就失效，需要重新打包；
  要长期用请到 dashboard 预留固定域名；
- 三种包的区别：`-usb` 需 `adb reverse`，无后缀是局域网 Wi-Fi 版，
  `-public` 是公网版（任意网络可用）。

## 八、2026-11-17 复盘：公网地址变了，手机 App 仍报「网络异常」

### 现象

- 电脑/手机浏览器打开 cpolar 公网地址正常，网页接口有数据；
- 手机 App 打开能显示静态界面，但所有接口报「网络异常 / 请求失败」；
- 服务端、Nginx、网关都正常（本机 `curl --noproxy "*" http://127.0.0.1/api/music/banners` 返回 200）。

### 根因

APK 是 WebView 壳（页面从本地 `http://127.0.0.1:8099` 加载），**接口地址在打包时被写死**：

```text
APK v1.5.1-public 内置：https://280a03e7.r11.cpolar.top/api
当前真实隧道：         https://7c4869c1.r60.cpolar.top
```

cpolar 免费版每次重启都会分配新的随机子域名（11-17 08:59 服务重启后换成了 `r60` 那个），
旧域名的 DNS 还在，但 cpolar 边缘返回 `404 domain doesn't exist`，所以 App 里所有请求
全部失败。也就是说：**「网站部署好了」和「App 能用」是两件事，APK 里的基址必须跟着隧道域名走。**

### 修复（已落地）

1. App 增加运行时服务器地址：`src/utils/server.js` + 「设置 → 服务器」，地址存
   `localStorage.km_api_base`，改完点「保存并重新加载」立即生效，**以后换域名不用重装**；
2. APK 启动自检：连不上接口时弹窗提示当前地址，并可一键跳到设置页；
3. 版本升到 **1.5.2**，用当前域名重新打包：
   `kumao-web\public\downloads\KuMao-Android-v1.5.2-public.apk`；
4. 公网下载：`https://7c4869c1.r60.cpolar.top/downloads/KuMao-Android-v1.5.2-public.apk`。

### 以后再遇到

1. 先看当前隧道域名：dashboard → 状态，或 `%USERPROFILE%\.cpolar\logs\` 最新日志里的 `Url`；
2. 手机 App →「设置 → 服务器」，填 `https://<新域名>/api` → 保存；
3. 要一劳永逸：cpolar 预留固定子域名（写进 `cpolar.yml` 的 `hostname`），域名就不再变。
