# 主播直播控制台与复盘

## 页面

| 路由 | 页面 | 说明 |
|---|---|---|
| `/studio/live/:id` | 直播控制台 | 主播实时画面、数据概览、播放队列、弹幕/礼物/榜单/歌单互动 |
| `/studio/report/:sessionId` | 本场复盘 | 单场 KPI、在线曲线、礼物分布、观众画像与结算状态 |
| `/studio/earnings` | 礼物收益 | 礼物收益汇总、明细筛选、分页与提现入口 |

## 控制台

- 直播中卡片显示红色 LIVE 徽标与每秒自增的已播时长。
- 在线、观看、点赞、礼物、新增粉丝数值变化时会做 300ms 数字滚动。
- 未开播时显示封面与等待推流占位；开播后自动接入 HTTP-FLV/HLS 实时画面。
- 观众端直播舞台按 16:9 全宽展示，不再用 `max-height` 压成带黑边的窄画面。
- 点击「开始直播」时，如果 SRS 上还没有主播推流，live-service 会自动启动 ffmpeg 生成一路演示画面（直播间标题、主播名、分类）并推到 `live/room_{id}`；如果主播已用 OBS/手机推流，则保留主播自己的画面。结束直播会同时停止自动推流进程。
- 需要把实时控制台内容作为直播画面时，使用 OBS「浏览器源」（不要用「窗口采集」，否则会拍到 OBS 自身形成递归）。地址：
  `http://<电脑IP>:5173/#/studio/live/{roomId}/broadcast`
  分辨率设为 1920×1080；直播控制台「推流地址」区域也提供「复制 OBS 画面地址」和「预览画面」。
  OBS 操作顺序：删除原来的「窗口采集」源 → 添加「浏览器源」并粘贴上面的地址 → 宽高设为 1920×1080 → 在「设置 → 直播」中选择自定义 RTMP，服务器 `rtmp://127.0.0.1:1935/live`，串流密钥填控制台推流地址中的 `room_{id}?token=...` → 开始推流，再回到控制台点击「开始直播」。此时 SRS 已有主播流，自动演示推流会自动跳过，观众看到的就是浏览器源里的实时画面。
- 控制台「OBS 自动推流设置」支持填写 OBS WebSocket 地址（默认 `ws://127.0.0.1:4455`）和密码；开启后点击「开始直播」会自动把当前直播间推流地址写入 OBS 并启动 OBS 推流。OBS 不可用或密码错误时会回退到自动演示画面。
- 右侧互动栏固定 380px，包含弹幕、礼物、榜单、歌单四个 Tab；「设置歌单」保存后按顺序进入待唱队列，未设置时队列为空，不使用热歌榜兜底。
- 控制台通过 WebSocket 实时推送 `NOW_PLAYING`（当前歌曲、演唱者、封面、播放进度、队列位置），直播画面页与观众端会同步更新，不需要轮询。
- 结束直播会弹出自绘确认层，确认后生成 sessionId 并把报告写入浏览器本地 `km_live_reports_v1`，随后跳转本场复盘。

自动推流可通过环境变量调整：

```text
LIVE_AUTOPUSH_ENABLED=true       # false 关闭自动推流
LIVE_AUTOPUSH_FFMPEG=ffmpeg      # ffmpeg 可执行文件路径
LIVE_AUTOPUSH_WIDTH=1280
LIVE_AUTOPUSH_HEIGHT=720
LIVE_AUTOPUSH_FPS=25
LIVE_AUTOPUSH_BITRATE=1800k
```

## OBS 自动推流

控制台「推流地址」区域提供「OBS 自动推流设置」，配置一次即可：

1. OBS → 工具 → WebSocket 服务器设置，确认已启用，记下端口（默认 `4455`）和密码。
2. 控制台会优先读取本机 `%APPDATA%\obs-studio\plugin_config\obs-websocket\config.json`，自动填入 OBS WebSocket 地址和密码；也可以手动填写。
3. 打开「自动写入推流地址并开始推流」，并选择画面来源：
   - **主播电脑屏幕**：自动创建/切换到「酷猫屏幕直播」场景，复用 OBS 的「显示器采集」源，适合主播分享自己的电脑桌面；请把 OBS 最小化，避免把 OBS 窗口一起拍进去。
   - **直播画面页**：自动创建/切换到「酷猫直播」场景，添加 1920×1080 的「浏览器源」；可选择直播画面页、首页、排行榜、歌单广场、MV 专区、直播广场、本直播间，或填写自定义公开页面地址。
   两种模式都会自动设置推流地址并启动 OBS，不再使用 OBS 原来的窗口采集/显示器采集场景。
3. 点击「开始直播」后：
   - 前端连接 OBS WebSocket；
   - 通过 `SetStreamServiceSettings` 写入当前直播间的 RTMP 服务器和串流密钥；
   - 通过 `StartStream` 启动 OBS 推流；
   - 后端收到 `skipAutoPush=true`，不再启动 ffmpeg 演示推流，避免双推流。
4. OBS 已在推流但目标地址不是当前直播间时，会先 `StopStream`，再切换到当前地址重新开始。
5. 点击「结束直播」并确认后，会先通过 OBS WebSocket 执行 `StopStream` 停止 OBS 推流，再调用后端下播接口，避免 OBS 仍在推流导致直播间重新变成直播中。
6. OBS WebSocket 不可用或密码错误时，自动回退到 ffmpeg 演示推流，并在控制台提示。


## 本场复盘

- 报告优先读取控制台结束时写入本地存储的本场数据；直接访问不存在的 sessionId 时使用内置演示数据。
- 在线曲线为原生 SVG `<polyline>`，带网格、hover 十字线和读数。
- 「导出报告」下载 JSON 文件；「再来一场」跳转 `/studio/live/:id/prepare`，该路由会回到主播工作台并复用原直播间配置打开发布弹窗。

## 礼物收益

- 数据来源：`GET /api/live/live/gifts/received`，按当前主播过滤；直播间名称来自 `GET /api/live/live/rooms/mine`。
- 今日/本月/累计与可提现余额由礼物记录实时计算；今日之后的记录按待结算展示，昨日及更早按已结算展示。
- 主播可在「礼物收益 → 收款账户」绑定支付宝或微信，绑定信息保存到 `anchor_apply.pay_type / pay_account / pay_name`；未绑定时点击提现会直接打开绑定弹窗。
- 提现按钮会校验收款账户并提交提现确认，后续接入实际打款审核。
