## 三、核心设计

### 1. 统一鉴权
- `user-service` 签发 JWT，payload 携带 `userId / username / role / device`
- 网关 `AuthGlobalFilter` 校验并向下游透传 `X-User-Id / X-Username / X-Role / X-Device`
- 业务服务通过 `UserContextInterceptor` 还原 `LoginUser`，`UserContext.requireUserId()` / `requireAdmin()` 做二次校验
- 多端登录策略：Redis 存 `kumao:login:token:{userId}:{device}`，`EXCLUSIVE` 时清除其它设备

### 2. 网关限流与降级
- Sentinel 网关规则：全局 API 200 QPS/IP，写接口（评论/弹幕/文件）30 QPS
- 阻塞处理器返回统一 JSON：`{"code":429,"message":"访问过于频繁，请稍后再试"}`
- `RequestRateLimiter`（Redis 令牌桶）对 user-service 路由做二级限流

### 3. 直播链路
```
主播 OBS ──RTMP──> SRS ──HTTP-FLV（低延迟）/ HLS（兜底）──> 观众播放器
                     │
                     ├─ on_dvr ──> live-service 生成回放地址（MinIO/本地）
                     └─ HTTP-FLV 低延迟备选

观众 ──WebSocket(/ws/live)──> live-service ──> 弹幕与 STREAM_STATUS 房间广播
                                    │
                                    └──RabbitMQ──> 弹幕异步落库
```
- 在线人数：Redis Set `kumao:live:online:{roomId}`，sessionId 进出增减
- 推流鉴权：HMAC-SHA256(stream:anchorId, pushKey)，防非法推流
- 敏感词：DFA 前缀树，命中即拒

### 4. 检索与降级
- ES 索引 `kumao_search`，统一文档结构 `type + bizId`
- 业务服务数据变更通过 `/internal/search/sync` 增量同步
- ES 不可用时 `FallbackSearchService` 使用 MySQL LIKE 检索兜底
- 后台支持手动全量重建索引

### 5. 异步消息
| 队列 | 生产者 | 消费者 |
|---|---|---|
| `kumao.play.record` | comment-service（前端投递） | comment-service（落库 + 播放量+1） |
| `kumao.live.danmaku` | live-service（WS 消息） | live-service（弹幕落库） |

### 6. 收益模型（模拟）
- 音乐人：每 1000 次播放折算 10 虚拟币；直播礼物按 70% 折算
- 广告制作人：曝光/点击按配置比例折算
- 提现走「申请 → 管理员审核 → 生成负向收益流水」

## 四、数据库设计

| 模块 | 表 |
|---|---|

| comment | `song_comment`、`song_like`、`play_record` |

| live | `live_room`、`live_danmaku`、`live_gift`、`live_gift_record`、`live_coin` |
| vip | `vip_package`、`vip_order`、`vip_member` |

## 五、前端结构

- `kumao-web`：Vue3 + Vite + Element Plus + Pinia + ECharts
  - 用户端：首页、排行榜、歌手、歌单、MV、直播（WebSocket 弹幕）、搜索、会员、音乐人主页
  - 工作台：音乐人 / 主播 / 广告制作人
  - 管理后台：17 个管理页面
- `kumao-uniapp`：APP 端（H5/小程序/App），复用同一 API
- `kumao-desktop`：Electron 壳，加载 PC Web，`device=DESKTOP` 可访问桌面专属接口

## 六、可扩展点

- JWT 改为非对称签名（RS256）+ 网关公钥校验
- 榜单改为实时计算（Flink/定时任务）而非缓存快照
- 播放记录、弹幕写入 ClickHouse 做大数据分析
- 直播礼物收益结算、广告投流支付对账接入真实渠道
