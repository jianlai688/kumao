# 评论与直播弹幕内容安全

评论和直播弹幕采用「AI 先审、自动放行、风险内容交管理员」的同步审核流程：

1. 用户发送内容时，业务服务先检查 `sys_user.muted_until`，仍在禁言期内直接拒绝。
2. 调用 `review-service` 内部接口 `POST /internal/ai/moderate` 做 AI 审核。
3. 审核结果为 `PASS` 且风险分低于阈值时，内容自动通过：
   - 评论立即写入并出现在歌曲评论区；
   - 弹幕立即广播到直播间并异步落库。
4. 其余结果（`REVIEW`、`REJECT`、风险分达到阈值、审核服务不可用）不能公开展示：
   - 评论 / 弹幕仍保存，状态置为 `2`（待管理员复核）；
   - 弹幕不广播，只向发送者回一条系统提示；
   - 管理员在「AI审核工作台」或评论 / 弹幕管理页复核，通过后改为 `0`，驳回改为 `1`。
5. AI 审核不再自动禁言用户；禁言仅保留为独立的管理/风控能力。

## 状态定义

### 评论 `song_comment.status`

| 值 | 含义 | 是否公开 |
|---|---|---|
| `0` | 已通过 / 正常 | 是 |
| `1` | 已驳回 / 已屏蔽 | 否 |
| `2` | 待管理员复核 | 否 |

### 弹幕 `live_danmaku.status`

| 值 | 含义 | 是否公开 |
|---|---|---|
| `0` | 已通过 | 是，进入历史记录 |
| `1` | 已驳回 / 已屏蔽 | 否 |
| `2` | 待管理员复核 | 否 |

两张表同时保存 `ai_decision`、`ai_risk_score`、`ai_source`、`ai_reasons`，供管理员查看 AI 建议和原因。

## 配置

```yaml
kumao:
  moderation:
    reject-risk-score: 35      # AI 风险分达到该值即不自动通过
```

评论服务到审核服务的 Feign 超时为 12 秒，直播服务为 8 秒。超时会按「审核不可用」处理，内容进入待管理员复核，不会自动放行。

## 数据库

执行 `sql/16-content-moderation-queue.sql`，为评论和弹幕增加 AI 审核字段及弹幕状态字段。脚本可重复执行。

## 内部接口

- `GET  /internal/users/{id}/muted`：查询用户是否处于禁言期
- `POST /internal/users/{id}/mute?minutes=60`：禁言用户（管理/风控调用）
- `POST /internal/ai/moderate`：AI 内容审核（comment-service / live-service 调用）

`review-service` 的 AI 模型不可用时会自动降级到本地规则；服务间调用异常时业务侧采用「转管理员复核」策略，保证风险内容不会因审核故障被自动公开。

## 管理端复核

- AI审核工作台：评论、直播弹幕分类只加载 `status=2` 的待复核内容；管理员点击通过 / 驳回后调用业务 admin 接口并写入审核日志。
- 评论管理：`GET /api/comment/comments/admin/page?status=2`，`PUT /api/comment/comments/admin/{id}/status?status=0|1`。
- 弹幕管理：`GET /api/live/live/danmaku/admin/page?status=2`，`PUT /api/live/live/danmaku/admin/{id}/status?status=0|1`。
