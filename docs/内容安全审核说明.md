# 评论与直播弹幕内容安全

评论和直播弹幕不再进入管理员前置审核队列：

1. 用户发送内容时，业务服务先检查 `sys_user.muted_until`，禁言期内直接拒绝。
2. 调用 `review-service` 内部接口 `POST /internal/ai/moderate` 做 AI 审核。
3. 审核返回 `REJECT` 或风险分达到阈值时：
   - 不写入评论 / 不广播、不持久化弹幕；
   - 自动禁言发送用户（默认 60 分钟）；
   - 评论接口返回 403，直播弹幕通过 WebSocket 发送系统提示。
4. 其余内容立即展示，不再等待管理员审批。

## 配置

```yaml
kumao:
  moderation:
    mute-minutes: 60          # AI 判定违规后的禁言时长
    reject-risk-score: 35     # 风险分达到该值即按违规处理
```

## 数据库

执行 `sql/15-moderation.sql`，为 `sys_user` 增加 `muted_until` 字段。

## 内部接口

- `GET  /internal/users/{id}/muted`：查询用户是否处于禁言期
- `POST /internal/users/{id}/mute?minutes=60`：禁言用户
- `POST /internal/ai/moderate`：AI 内容审核（comment-service / live-service 调用）

`review-service` 的 AI 模型不可用时会自动降级到本地规则；本地规则仍会拦截明显风险内容，服务间调用异常时业务侧采用放行策略，避免评论 / 弹幕功能整体不可用。
