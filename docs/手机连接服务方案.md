# 手机连接酷猫服务 · 实施方案

> 生成时间：2026-11-13　目标机：本机（Windows，`D:\kumao`）
> 结论先行：**服务端已经在监听所有网卡，手机能不能连，只差"防火墙放行"这一步**；另外直播链路要单独改一个地址。

| SRS 直播 | ✅ `1935`(RTMP) / `8088`(HLS) / `1985`(API) 已发布，端口可达 | 当前无推流，`.m3u8` 返回 404 属正常 |

| WebSocket 路由 | ✅ 网关 `/ws/live/**` → `lb:ws://live-service` | 弹幕、直播状态推送可通 |

**一句话**：先把防火墙三条端口放行，手机连同一个 Wi-Fi，装现成 APK 就能用；要直播再加一条 `SRS_PLAY_HOST` 配置。

## 二、四种方案怎么选

| 方案 | 适用场景 | 耗时 | 是否改代码 |
| --- | --- | --- | --- |
| **A. 现成 APK + 放行防火墙**（推荐先用） | 只想在手机上跑起来看看 | 5 分钟 | 否 |
| **B. H5 调试（uniapp dev）** | 开发期反复改 UI/接口 | 2 分钟 | 否，热更新 |
| **C. 重新打包 APK** | IP 变了 / 要发版 / 要给别人的手机装 | 15 分钟 | 改构建参数 |
| **D. 外网访问（不在同一 Wi-Fi）** | 手机用 4G、异地演示 | 30 分钟 | 改地址 + 隧道 |
| **E. USB 数据线调试**（本机手机推荐，见 `docs/手机USB调试.md`） | 手机没连 Wi-Fi / 不想动防火墙 | 10 秒 | 需 127.0.0.1 版 APK |

## 三、方案 A：装现成 APK（最快落地）

现成产物：`D:\kumao\kumao-mobile-apk\app\build\outputs\apk\debug\app-debug.apk`

### 1. 放行防火墙（必须，管理员 PowerShell）

```powershell
# 以管理员身份打开 PowerShell，然后执行（只放行本网段，别用 Any 放开公网）
New-NetFirewallRule -DisplayName "Kumao-8080-网关"   -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080 -Profile Any -RemoteAddress 192.168.20.0/24
New-NetFirewallRule -DisplayName "Kumao-5173-前端"   -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5173 -Profile Any -RemoteAddress 192.168.20.0/24
New-NetFirewallRule -DisplayName "Kumao-8088-HLS"    -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8088 -Profile Any -RemoteAddress 192.168.20.0/24
New-NetFirewallRule -DisplayName "Kumao-1935-RTMP"   -Direction Inbound -Action Allow -Protocol TCP -LocalPort 1935 -Profile Any -RemoteAddress 192.168.20.0/24

# 校验
Get-NetFirewallRule -DisplayName "Kumao-*" | Select-Object DisplayName,Enabled,Profile
```

> 为什么必须做：`Get-NetConnectionProfile` 显示以太网是 **Public（公用）**，Windows 默认拒绝入站；当前没有 JDK17/Node 的放行规则。本机访问 8080 成功只说明"服务在监听"，不代表手机能进来。
> 如果手机连的是电脑热点（`192.168.137.x`），把 `-RemoteAddress` 换成 `192.168.137.0/24` 再加一遍。

### 2. 手机侧

1. 手机连**和电脑同一个路由器**的 Wi-Fi（必须是 `192.168.20.x` 网段，不要连访客 Wi-Fi / 别开 AP 隔离）。
2. 手机浏览器先验一下：打开 `http://192.168.20.103:8080/api/music/rank/hot?limit=1`，能看到 JSON 就说明网络通了。
3. 安装 APK（数据线 / 微信传文件 / 二维码都行），或用：

```powershell
adb install -r "D:\kumao\kumao-mobile-apk\app\build\outputs\apk\debug\app-debug.apk"
```

4. 打开 App → 登录 `zhangsan / 123456`（或 `admin / admin123`）→ 首页榜单能出数据即成功。

> 注意：APK 里接口地址是编译期写死的 `192.168.20.103:8080`。换 Wi-Fi、路由器重分配 IP 后 App 会连不上，此时走方案 C，或在路由器上给这台电脑做 **DHCP 地址保留**（推荐，一劳永逸）。

## 四、方案 B：H5 调试（开发期首选，不用打包）

uniapp 的 dev server 已经把 `/api`、`/ws`、`/static` 代理到 `127.0.0.1:8080`，所以**页面里用相对路径就行，不用改任何地址**：

```powershell
cd D:\kumao\kumao-uniapp
npm run dev:h5      # 监听 0.0.0.0:5174，代理已配好
```

手机浏览器打开：`http://192.168.20.103:5174`

- 改代码 → 手机刷新即生效，不用重新打包。
- 已有的 PC 前端 `http://192.168.20.103:5173` 同理可直接在手机浏览器打开（当前已在运行）。
- 代价：跑在浏览器里，原生能力（后台播放、文件选择、状态栏）不如 APK。

## 五、方案 C：重新打包 APK（换 IP / 发版）

原理：uniapp H5 产物里的 `VITE_API_BASE` 决定"手机上往哪台机器发请求"，打包前注入即可。

```powershell
# 1) 用目标地址构建 H5（必须是绝对地址，不能是 127.0.0.1 或相对路径）
$env:VITE_API_BASE = 'http://192.168.20.103:8080/api'
cd D:\kumao\kumao-uniapp
npm run build:h5

# 2) 产物替换进 APK 的本地站点目录
$dst = 'D:\kumao\kumao-mobile-apk\app\src\main\assets\www'
Remove-Item "$dst\*" -Recurse -Force
Copy-Item 'D:\kumao\kumao-uniapp\dist\build\h5\*' $dst -Recurse -Force
```

3) 打包：Android Studio 打开 `D:\kumao\kumao-mobile-apk` → `Build > Build App Bundle(s)/APK(s) > Build APK(s)`
　（已有 `local.properties` 指向 SDK；命令行也可以 `gradle assembleDebug`，前提是 PATH 里有 gradle）
4) 产物：`D:\kumao\kumao-mobile-apk\app\build\outputs\apk\debug\app-debug.apk`

打包要点（都已具备，改的时候别破坏）：
- `vite.config.js` 的 `base: './'`，否则 `127.0.0.1:8099` 下资源 404；
- `AndroidManifest.xml` 的 `usesCleartextTraffic="true"`，否则 Android 9+ 拒绝 http 明文；
- `assets/www` 由 `LocalAssetServer` 在手机本地以 `http://127.0.0.1:8099` 提供，接口地址必须走绝对地址；
- WebSocket 地址由 API 基址推导（`ws://192.168.20.103:8080`），不用单独配。

## 六、直播链路（要开播/看播才需要）

`live-service` 的 HLS 播放地址 = `${SRS_PLAY_HOST}/live/{stream}.m3u8`，默认 `http://127.0.0.1:8088`，手机端必然黑屏。

```powershell
# 重启 live-service 时注入（IDE 里加到 Environment variables，或命令行）
$env:SRS_PLAY_HOST = 'http://192.168.20.103:8088'
$env:SRS_PUSH_HOST = ''          # 留空：自动取本机局域网 IP，手机推流地址才对
```

- 推流（主播手机 → PC）：`rtmp://192.168.20.103:1935/live/{stream}?key=...`，需放行 `1935`；
- 拉流（观众）：`http://192.168.20.103:8088/live/{stream}.m3u8`，需放行 `8088`；
- 验证：`curl.exe -I http://192.168.20.103:8088/live/room_1.m3u8`，有推流时应返回 200 + `application/vnd.apple.mpegurl`。

## 八、故障排查对照表

| 现象 | 最可能原因 | 处理 |
| --- | --- | --- |
| 手机转圈/超时，电脑本机能开 | 防火墙未放行 / 手机不在同网段 / 路由器开了 AP 隔离 | 加规则；确认手机 IP 也是 `192.168.20.x`；关 AP 隔离或用主 Wi-Fi |
| 能登录但所有图片裂 | 接口返回相对路径且前端没拿到绝对基址 | 方案 B 用 dev 代理；方案 C 确认 `VITE_API_BASE` 是绝对地址 |
| App 打开是白屏 | APK 内 `assets/www` 与 `base:'./'` 不匹配 | 重新按方案 C 拷贝产物，确认用 `./assets/...` |
| 直播黑屏、控制台 127.0.0.1:8088 | `SRS_PLAY_HOST` 未改 | 按第六节注入并重启 live-service |
| 弹幕连不上、WS 报错 | 用了 127.0.0.1 或代理没开 ws | H5 走 5173/5174（已配 `ws:true`）；APK 确认 API 基址正确 |
| 昨天能用今天不能用 | 路由器 DHCP 换了 IP | 给电脑做地址保留，或重打包 |
| 登录 401 循环 | token 过期/清过缓存 | 重新登录；必要时清 App 数据 |
| 手机能开但很慢 | 走了 2.4G 或电脑在跑虚拟网卡抢路由 | 手机连 5G Wi-Fi；确认 PC 默认路由走以太网 |

## 九、方案 D：不在同一局域网（外网访问，可选）

| 方式 | 适合 | 做法要点 |
| --- | --- | --- |
| Cloudflare Tunnel | 临时演示、无公网 IP | `cloudflared tunnel --url http://127.0.0.1:8080` 得到 https 域名 → 把该域名填进 `VITE_API_BASE` 重打包 |
| frp / nginx 反代 | 有云服务器 | 服务器反代到 8080/8088，注意 WS 要带 `Upgrade` 头 |
| Tailscale / ZeroTier | 自己手机长期用 | 手机装客户端组虚拟局域网，用虚拟 IP 访问，**不用改公网、最安全** |

安全提醒：网关虽然有 JWT 和 Sentinel 限流（200 QPS/IP），但没有来源白名单。**不要**把 8080/8101~8111/3306/6379/9000 直接映射到公网；演示结束及时关隧道。

## 十、推荐执行顺序

1. **管理员 PowerShell 跑第三节第 1 步**（放行 4 个端口）——这是当前唯一硬阻塞；
2. 手机连同一 Wi-Fi，按第七节 1~4 项验收；
3. 需要开播再看第六节（改 `SRS_PLAY_HOST`）；
4. 需要长期稳定 → 路由器给 `192.168.20.103` 做 DHCP 保留；
5. 需要给别的手机/异地 → 方案 C 重打包 + 方案 D 隧道。

### 附：如果你问的其实是"把 DSH 控制台（`http://127.0.0.1:54103`）放到手机上"

那和上面的业务服务不是一回事：该端口**只绑定 127.0.0.1**（实测），其他设备直接访问不到，必须额外做反向代理/端口转发再放行防火墙；而且它默认没有对外鉴权，**不建议直接暴露到局域网或公网**，临时用建议套 Tailscale 这类内网穿透。需要的话我可以单独出一份这个方案。
