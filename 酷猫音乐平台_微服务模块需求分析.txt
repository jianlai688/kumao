====================================================================
                酷猫音乐平台 · 微服务模块需求分析
====================================================================
依据文档：《酷猫音乐平台功能需求分析说明书》V1.0（2026-10-18）
技术栈  ：SpringBoot + SpringCloud + Vue3 / uniapp / Electron
系统架构：多端前端 → Gateway 网关 → 10 个业务微服务 + 中间件
中间件  ：Nacos、MySQL、Redis、MinIO、SRS、WebSocket、
          Elasticsearch、RabbitMQ、Sentinel
模块规模：11 个（1 个网关 + 10 个业务微服务）
--------------------------------------------------------------------

【模块速查】
1、 gateway           网关服务    统一入口、路由、鉴权、限流熔断
2、 user-service      用户服务    注册登录、账号管理、角色权限
3、 music-service     音乐服务    歌曲、歌手、榜单、MV
4、 playlist-service  歌单服务    歌单创建维护、收藏
5、 comment-service   互动服务    评论、我喜欢、播放记录
6、 file-service      文件服务    图片/音频/歌词/视频统一存储
7、 live-service      直播服务    直播间、弹幕、礼物、回放
8、 search-service    检索服务    ES 全文检索与索引同步
9、 vip-service       会员服务    套餐、开通、付费权限校验
10、musician-service  音乐人服务  入驻、作品、数据、收益
11、ad-service        广告服务    入驻、素材、投流、数据、投放收入


====================================================================
一、微服务模块需求明细
====================================================================

1、gateway 网关服务：接入层 · 统一入口
   职责：所有前端请求的唯一入口，完成路由、鉴权、跨域、限流熔断
   调用方：PC Web / Android APP / 电脑桌面客户端 / 后台管理系统
   1) 请求路由
       i. 按 url 将请求分发至对应业务微服务
       ii. 静态资源访问路由
       iii. WebSocket 长连接转发（弹幕、消息推送）
   2) 鉴权与登录控制
       i. Token 鉴权拦截，未登录请求直接拦截
       ii. 识别登录设备（PC Web / 桌面客户端 / APP），token 内携带设备类型
       iii. 同账号多端登录策略：互斥 / 共存可配置
       iv. 识别客户端请求来源，做接口权限适配（APP、桌面端专属接口隔离）
   3) 流量防护（集成 Sentinel）
       i. 网关级限流
       ii. 熔断
       iii. 降级，返回统一友好提示
   4) 基础设施能力
       i. 跨域处理
       ii. 基础请求日志打印

2、user-service 用户服务：账号体系
   职责：多端登录、账号管理、角色与权限管理
   调用方：三端 + 后台管理系统
   1) 用户注册
       i. 手机号注册（短信验证码校验）
       ii. 账号密码注册（密码加密存储）
   2) 登录
       i. 账号密码登录（PC / APP）
       ii. 手机号验证码登录（PC / APP）
       iii. QQ / 微信第三方 OAuth 登录（PC / APP）
       iv. 运营商一键登录（仅 APP）
       v. 登录成功签发 JWT Token，token 内携带设备类型
       vi. 单账号多端登录策略控制（互斥 / 共存）
   3) 账号管理
       i. 退出登录
       ii. 单点下线（踢掉其他端设备）
       iii. 密码重置与找回
       iv. 修改个人资料（头像、昵称、简介，三端同步更新）
   4) 权限管理
       i. 角色划分：普通用户 / 主播 / 音乐人 / VIP 会员 / 管理员
       ii. 主播申请提交，管理员后台审核开通权限
       iii. 音乐人认证申请提交与状态流转
       iv. 后台查看用户、启用 / 禁用账号
   5) 登录记录
       i. 记录登录设备类型
       ii. 记录登录时间
       iii. 后台可查询用户登录设备记录

3、music-service 音乐服务：歌曲 / 歌手 / 榜单 / MV
   职责：承载点播音乐核心业务
   调用方：三端 + 后台；被 playlist、comment、musician、search 调用
   1) 歌手管理
       i. 歌手信息维护（新增、编辑、删除）
       ii. 歌手信息查询
   2) 歌曲管理
       i. 歌曲元数据维护
       ii. 歌曲上下架
       iii. 歌曲基础查询接口(按地区显示歌曲（国外国内粤语）)
   3) 歌词
       i. LRC 歌词解析
       ii. 前端歌词同步滚动展示
   4) 榜单
       i. 热门榜
       ii. 新歌榜
       iii. 飙升榜
       iv. 榜单数据 Redis 缓存
   5) MV 视频模块
       i. 管理员上传 MV 视频与封面，填写名称并关联歌手
       ii. MV 上下架、编辑、删除
       iii. MV 列表分页查询
       iv. MV 详情与播放
       v. 对接 vip-service，控制高清 MV 仅 VIP 观看

4、playlist-service 歌单服务
   职责：歌单的创建与维护
   调用方：三端用户；依赖 music-service 获取歌曲信息
   1) 歌单维护
       i. 创建歌单（公开 / 私有）
       ii. 编辑歌单
       iii. 删除歌单
   2) 歌单内歌曲
       i. 添加歌曲到歌单
       ii. 从歌单移除歌曲
   3) 歌单收藏
       i. 收藏他人公开歌单
       ii. 取消收藏
   4) 歌单查询
       i. 歌单分页查询
       ii. 公开歌单 / 我的歌单 / 我收藏的歌单

5、comment-service 互动服务：评论 / 播放记录 / 喜欢
   职责：承载用户互动数据
   调用方：三端用户；播放记录经 RabbitMQ 异步写入
   1) 歌曲评论
       i. 发表歌曲评论
       ii. 歌曲评论列表查询
       iii. 供后台评论管理调用
   2) 我喜欢（红心歌曲）
       i. 添加红心
       ii. 取消红心
       iii. 我的喜欢列表
   3) 播放记录
       i. 前端播放歌曲时投递消息到 RabbitMQ
       ii. 异步落库保存播放记录
       iii. 记录播放端类型（PC / APP）
       iv. 播放记录查询

6、file-service 文件服务：统一存储
   职责：统一文件上传、校验、存储与删除
   调用方：所有涉及上传的服务与端（音乐人、主播、广告制作人、后台）
   1) 文件上传
       i. 图片（头像、封面、轮播图）
       ii. mp3 音频
       iii. lrc 歌词
       iv. 直播间封面图片
       v. MV 视频
   2) 文件校验
       i. 文件后缀校验
       ii. 文件大小限制
   3) 存储对接
       i. 对接 MinIO 对象存储
       ii. 上传成功返回资源访问 URL
   4) 文件删除
       i. 文件删除接口

7、live-service 直播服务：音乐直播
   职责：承载音乐直播全部业务
   调用方：主播端、用户端、后台；依赖 file、search、vip、Redis、RabbitMQ
   1) 直播间管理
       i. 创建直播间（标题、简介、封面、分类：弹唱 / 电台 / 翻唱）
       ii. 修改直播间信息
       iii. 关闭直播间
       iv. 删除直播间
       v. 获取 SRS 推流地址与观众拉流播放地址
       vi. 直播间状态管理（未开播 / 直播中 / 已下播）
   2) 直播广场
       i. 分页展示正在直播的房间（封面、标题、主播名、在线人数）
       ii. 按分类筛选
       iii. 搜索直播间（调用 search-service）
   3) 在线人数统计
       i. Redis 实时存储在线人数
       ii. 用户进入 / 离开房间更新计数
   4) 弹幕模块（WebSocket）
       i. 进入直播间建立 ws 连接
       ii. 发送弹幕
       iii. 敏感词过滤
       iv. 广播给房间内所有在线用户
       v. 弹幕投递 RabbitMQ 异步持久化
       vi. 弹幕分页历史记录
       vii. 后台弹幕管理
   5) 虚拟礼物打赏（模拟）
       i. 礼物预设（鲜花、音符、爱心等）
       ii. 赠送消耗平台虚拟币
       iii. 赠送广播特效消息
       iv. 记录礼物记录
       v. 主播查看收到礼物清单
   6) 主播后台
       i. 查看直播间实时在线人数
       ii. 查看礼物记录
       iii. 一键下播
   7) 直播间权限控制
       i. 仅主播角色可创建直播间、获取推流地址
       ii. 观众仅可拉流观看、发弹幕、送礼物
       iii. 推流地址鉴权，防止非法推流
   8) 直播回放
       i. SRS 录制直播视频并存储至 MinIO
       ii. 下播自动生成回放
       iii. 用户点播回看
   9) 后台直播管理
       i. 直播间管理
       ii. 封禁违规直播间
       iii. 礼物配置管理
       iv. 直播数据统计

8、search-service 检索服务：ES 全文检索
   职责：基于 Elasticsearch 提供统一全文检索能力
   调用方：三端 + 后台；由各业务服务同步数据
   1) 索引维护
       i. 歌曲、歌手、歌单、直播间、音乐人数据同步到 ES 索引
       ii. 后台手动触发索引同步
       iii. 检索数据监控
   2) 全文检索
       i. 关键词同时检索歌曲、歌手、歌单、直播间、音乐人
       ii. 分词搜索
       iii. 搜索关键词高亮展示
   3) 增量同步
       i. 业务数据新增自动同步
       ii. 业务数据修改自动同步
       iii. 业务数据删除自动同步
   4) 对外接口
       i. 提供给 PC、APP、桌面三端调用

9、vip-service 会员服务：VIP 与付费权限
   职责：会员套餐、开通、付费权限统一校验
   调用方：三端用户；被 music-service、live-service 调用校验权限
   1) 会员套餐管理
       i. 月卡
       ii. 季卡
       iii. 年卡
       iv. 后台套餐配置（模拟购买）
   2) 开通与状态管理
       i. 模拟下单与支付
       ii. 开通会员并记录有效期
       iii. 会员到期与续费
   3) 付费权限校验
       i. 付费歌曲播放权限校验接口
       ii. 高清 VIP 专属 MV 观看权限校验接口
       iii. 直播间 VIP 特权：专属弹幕颜色、入场特效
   4) 后台会员管理
       i. 会员记录查询
       ii. 会员数据统计

10、musician-service 音乐人服务：入驻 / 作品 / 收益
    职责：音乐人入驻、作品管理、数据统计与收益（模拟）
    调用方：音乐人端、用户端（主页）、后台；依赖 file、music、live
    1) 入驻认证申请
        i. 提交认证（艺名、真实姓名、音乐风格、个人简介、头像、代表作说明）
        ii. 状态流转：待审核 → 通过 / 拒绝（拒绝附原因）
        iii. 通过后自动获得音乐人角色并开通工作台权限
        iv. 后台审核与取消资格
    2) 音乐人主页
        i. 展示头像、艺名、简介、风格、粉丝数、总播放量
        ii. 展示发布的歌曲、专辑列表
        iii. 普通用户关注 / 取关音乐人
        iv. 新歌发布通知（WebSocket 推送）
    3) 作品管理
        i. 上传原创歌曲（音频、封面、LRC 歌词；歌曲名、语种、风格、
           是否付费、发行时间）
        ii. 创建专辑
        iii. 歌曲 / 专辑编辑、上下架、删除
        iv. 上传歌曲自动同步至 music-service 歌曲库
        v. 歌曲审核机制：上传后待审核，管理员通过后上架
    4) 数据统计
        i. 作品播放量趋势（日 / 周 / 月）
        ii. 收藏量、评论数、分享数
        iii. 粉丝增长趋势与地域分布
        iv. 单曲排行榜
    5) 收益管理（模拟）
        i. 播放收益按虚拟比例折算虚拟币
        ii. 礼物收益对接 live-service
        iii. 收益明细查询
        iv. 提现申请（模拟审核）
        v. 管理员查看收益汇总
    6) 权限控制
        i. 仅音乐人角色可访问工作台、上传作品
        ii. 只能管理自己的作品
        iii. 违规时管理员取消资格并下架全部作品

11、ad-service 广告制作人服务：入驻 / 素材 / 投放
    职责：广告制作人入驻、广告素材制作、投放管理与投流结算（广告主付费买量，不产生收益）
    调用方：广告制作人端、后台；依赖 file-service
    1) 入驻认证申请
        i. 提交认证（艺名 / 主体名称、真实姓名、广告类型、个人简介、
           头像、代表作说明）
        ii. 状态流转：待审核 → 通过 / 拒绝（拒绝附原因）
        iii. 通过后自动获得广告制作人角色并开通工作台权限
        iv. 后台审核与取消资格
    2) 广告素材管理
        i. 音频广告素材
        ii. 视频广告素材
        iii. 图文广告素材
        iv. 素材编辑、上下架、删除
        v. 管理员审核通过后进入可投放状态
    3) 广告投流管理（广告流量只能通过投流获得）
        i. 选择广告位（开屏、首页 banner、直播页、播放页）
        ii. 设置投放时段与目标人群，按广告位与天数报价
        iii. 支付投流费用后提交投放计划，管理员审核通过后开始投放
        iv. 投放计划暂停、续投、终止
    4) 数据统计
        i. 素材曝光量
        ii. 素材点击量
        iii. 点击率（CTR）
        iv. 投放地域分布、分时段趋势
        v. 单条素材数据对比排行榜
    5) 投流结算与投放收入（广告主不产生收益）
        i. 投流费用按广告位、投放天数计费，支付成功后才可提交审核
        ii. 广告主侧无收益管理、无提现，收益不属于广告主
        iii. 管理员查看投放收入（已支付投流费用）汇总
        iv. 投放暂停、续投、终止不影响已产生的投流费用
    6) 权限控制
        i. 仅广告制作人角色可访问工作台、上传素材、发起投放
        ii. 只能管理自己的素材与投放计划
        iii. 违规时管理员取消资格并下架全部广告素材


====================================================================
二、按端的模块归属（谁用哪些服务）
====================================================================

1、用户端：普通观众（PC Web / Android APP / 电脑桌面客户端）
   1) 账号与登录 → user-service
   2) 首页、榜单、歌手、歌曲播放、歌词 → music-service
   3) 歌单创建与收藏 → playlist-service
   4) 评论、我喜欢、播放记录 → comment-service
   5) MV 专区 → music-service + vip-service（高清权限）
   6) 音乐直播、弹幕、礼物 → live-service
   7) 全文检索 → search-service
   8) 会员中心 → vip-service

2、主播端：主播用户
   1) 主播权限申请 → user-service
   2) 创建直播间、获取推流地址 → live-service
   3) 开播 / 下播 / 在线人数 / 礼物记录 → live-service
   4) 直播封面、回放文件 → file-service

3、音乐人端：音乐人用户（工作台 + 主页）
   1) 入驻认证申请 → musician-service
   2) 作品上传、专辑管理 → musician-service + file-service
   3) 审核通过入库 → music-service（同步歌曲库）
   4) 播放 / 收藏 / 评论数据统计 → musician-service
   5) 收益与提现（模拟）→ musician-service + live-service（礼物收益）
   6) 主页展示与粉丝关注 → musician-service、search-service

4、广告制作人端：广告制作人用户（工作台）
   1) 入驻认证申请 → ad-service
   2) 素材上传与审核 → ad-service + file-service
   3) 广告位与投放计划 → ad-service
   4) 投放数据与收益（模拟）→ ad-service

5、管理端：管理员用户（PC 后台管理系统）
   1) 管理员登录、用户启停、设备记录、主播申请审核 → user-service
   2) 歌曲 / 歌手 / 歌单 / 评论 / 轮播 / 公告管理 → music、playlist、
      comment-service
   3) 直播间管理、封禁、弹幕、礼物、直播统计 → live-service
   4) MV 资源管理 → music-service
   5) 会员套餐与会员记录 → vip-service
   6) 音乐人审核、资格取消、收益统计 → musician-service
   7) 广告审核、广告制作人管理、投放数据 → ad-service
   8) ES 索引手动同步与检索监控 → search-service
   9) 基础数据看板 → 各服务数据聚合


====================================================================
三、模块依赖与中间件对应
====================================================================

1、Feign 调用关系
   1) gateway → 全部业务微服务（路由分发）
   2) music-service → vip-service（MV 高清权限校验）
   3) playlist-service → music-service（歌曲信息）
   4) comment-service → music-service（歌曲信息）
   5) musician-service → music-service（作品入库）
      musician-service → file-service（音频、封面、歌词）
      musician-service → live-service（礼物收益）
   6) live-service → search-service（直播间检索）
      live-service → file-service（封面、回放）
      live-service → vip-service（VIP 弹幕与入场特效）
   7) ad-service → file-service（广告素材）
   8) search-service ← 各业务服务数据同步（歌曲、歌手、歌单、
      直播间、音乐人）

2、中间件对应关系
   1) Nacos —— 服务注册与配置中心
   2) MySQL —— 业务数据持久化（单库按模块分表，共 10 个数据模块）
   3) Redis —— 榜单 / 首页推荐缓存、直播间在线人数实时计数
   4) MinIO —— 音频、图片、歌词、MV 视频、直播回放存储
   5) SRS —— 直播推流、拉流、录制
